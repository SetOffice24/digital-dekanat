# Цифровой деканат будущего — правила для ИИ-агентов

Прототип личного кабинета студента для конкурса. Общаться с командой на русском.

## Документы
- `docs/00-tz.md` — требования конкурса и критерии. Сверяться перед каждой фичей.
- `docs/01-research.md` — исследование и утверждённый состав разделов.
- `docs/02-architecture-brief.md` — задание архитектору.
- `docs/ARCHITECTURE.md` — архитектура (источник правды для разработки, после её появления).
- `docs/process-log.md` — журнал работы с ИИ. **После каждого значимого шага добавлять запись**: задача, модель/инструмент, ключевой промпт, результат, ошибки ИИ и как исправили. Это половина оценки по критерию «нейротехнологии».

## Жёсткие правила
- Только вымышленные данные. Никаких реальных ФИО, номеров зачёток, логинов вуза.
- Без логотипа реального вуза. На сайте — пометка «концепт для конкурса, не официальный сервис».
- Секреты (ключи ИИ, пароли БД) — только в переменных окружения на сервере, никогда в коде, в git и в браузере. `.env` в `.gitignore`.
- Каждый запрос к данным студента фильтруется по пользователю из сессии; доступ по чужому ID должен давать 404/403. На это — автотесты.
- Mobile-first: всё проверять на ширине 360 px.
- Сторонние шрифты/иконки/картинки — только с разрешающей лицензией; лицензию указывать.
- Ветка `main` — рабочая; push только по команде пользователя.

## Минимализм
Сначала ядро (вход, «Мой день», расписание, успеваемость, заявки, уведомления), потом фишки. Не добавлять разделы сверх утверждённого состава без согласования.
