## Подтверждённые находки

### SEC-01 · P1 · Произвольные HTTPS-адреса Web Push → SSRF

Места: `src/server/push.ts:30,46`, `src/app/api/push/route.ts:15`, `src/app/api/push/test/route.ts:8`.

`savePushSubscription` проверяет HTTPS и алфавит ключей, но не назначение адреса. Пользователь может зарегистрировать loopback/private IPv4/IPv6, произвольный порт или собственный домен. `sendPush` передаёт адрес библиотеке, использующей `https.request`. При настроенном VAPID пользователь может инициировать отправку кнопкой теста. Проверка Origin этому не препятствует: пользователь атакует со своей сессией.

Воспроизведение без сети: реальная функция приняла `https://127.0.0.1:8443/internal`, `https://10.0.0.1/private`, `https://[::1]/internal`; реальная библиотека с корректной парой P-256 сформировала запросы к этим адресам. Фактическая достижимость внутреннего сервиса зависит от сети и TLS; извлечение произвольного ответа пользователю не продемонстрировано. Это ограниченная HTTPS SSRF, а не доказанный захват сервера или чтение metadata по HTTP.

Исправление: allowlist точных доменов поддерживаемых push-провайдеров с корректными границами поддоменов; URL-парсер, HTTPS/443, запрет userinfo и неожиданных портов; защита разрешения DNS и egress от локальных/служебных сетей. Ограничить число подписок на пользователя, конкурентные отправки и время запроса. Учитывать Apple/Mozilla/Google, а не разрешать один провайдер. Старые записи перепроверять перед отправкой.

### SEC-02 · P2 · Прежняя учебная связь продолжает давать доступ к файлам и части посещаемости

Места: `src/server/files.ts:173`, `src/server/repos/teacher.ts:33`, `src/server/repos/attendance.ts:69,77`.

Журнал использует `teachesPair` с окном 150 дней. Загрузка вложений проверяет наличие любой пары за всё время. Преподаватель, потерявший текущую связь, при известном ID файла всё ещё получает материал/работу. В `courseAttendance` также нет текущего периода, а список студентов берётся из нынешнего состава группы: историческая пара может открыть сведения о новых студентах группы.

Воспроизведение на подменённом репозитории: для одной и той же связи проверка журнала вернула false, проверка файла — объект вложения. ID не является средством авторизации; получить его можно из прежнего доступа или сохранённой ссылки.

Исправление: единая политика доступа для журналов, файлов, посещаемости и знаний. Если архивные работы преподавателю должны оставаться доступны, разрешать именно архивные объекты по явному правилу, без автоматического доступа к новым работам и нынешнему составу группы. Новая библиотека знаний также использует исторические пары в `visibleWhere`, `teacherTargets`, `checkTarget` — включить её в эту унификацию.

### SEC-03 · P2 · Текущий преподаватель может менять текущие баллы старого семестра

Места: `src/server/repos/teacher.ts:79,90,132`.

`addGrade`, `deleteGrade`, `addGradesBulk` проверяют нынешние группу/дисциплину, но не семестр зачисления и не закрытие периода. Подставив enrollmentId за прошлый семестр того же студента/дисциплины, текущий преподаватель может добавить баллы или удалить CURRENT-оценку, даже если тогда преподавал другой человек. FINAL/RETAKE удалением здесь защищены — это не обход этой проверки.

Воспроизведение: `addGrade` создал запись для зачисления первого семестра при наличии только текущей связи. Выборка даже не запрашивает semester.

Исправление: проверять период зачисления и полномочия на его изменение в репозитории для всех трёх операций; закрытые периоды менять отдельным разрешённым процессом. Добавить журнал авторства/изменений оценок и тесты подмены enrollmentId/gradeId.

### SEC-04 · P2 · Ответ студента способен отменить параллельный отказ по заявке

Место: `src/server/repos/student.ts:115`.

`answerRequest` читает NEED_INFO, затем обновляет по id без условия прежнего статуса. Если деканат успеет отклонить заявку, ответ студента вернёт её в IN_REVIEW. В `changeRequestStatus` условное обновление уже есть, но обратная ветка его не использует.

Воспроизведение: после чтения NEED_INFO тест переключил состояние в REJECTED; вызов студента всё равно записал IN_REVIEW.

Исправление: условное `updateMany` по id, studentId и status=NEED_INFO; событие истории и обновление в одной транзакции, проверка count. При конфликте — понятный ответ с предложением обновить страницу.

### SEC-05 · P1 для восстановления реальных данных · Неполные и потенциально ложные резервные копии

Место: `deploy/backup.sh:3,6,8`.

Файловый архив содержит только `/app/data/uploads`; фото лежат в `/app/data/photos` и не копируются. После восстановления БД и архива останутся ссылки на отсутствующие фото. `pg_dump | gzip` выполняется в POSIX sh с `set -e`, который не гарантирует ошибку всей трубы при отказе pg_dump: успешный gzip может создать пустой архив с успешным кодом завершения. Запись сразу в окончательное имя также оставляет частичный файл при сбое.

Подтверждено чтением скрипта и путей хранения; реальное восстановление не выполнялось.

Исправление: копировать весь необходимый DATA_DIR, включая photos; явно проверять pg_dump либо использовать оболочку с pipefail; временные файлы → проверка архива → атомарное переименование; `umask 077`; согласованность БД и файлов; отдельная копия вне VPS, уведомление об ошибке, регулярное восстановление на тестовой среде. Наличие shell-скрипта не подтверждает, что cron настроен на сервере.

### SEC-06 · P2 · Защита файлов проверяет сигнатуры, а не безопасность документа

Места: `src/server/files.ts:59`, `src/server/knowledge/text.ts:14`, `src/app/library-actions.ts:60`.

Поддельный PDF с одним префиксом `%PDF-` и поддельный DOCX с ZIP-сигнатурой и строками `word/`, `[Content_Types].xml` проходят checkContent. Старые OLE-файлы проверяются только по заголовку и могут содержать макросы. Это не доказанный XSS/RCE: вложения отдаются attachment+nosniff и не исполняются приложением. Но проверка не позволяет считать документ безопасным для скачивания.

Новая библиотека реально разбирает PDF/DOCX в процессе приложения. Ограничение размера сжатого файла не ограничивает объём распаковки, число страниц и затраты CPU. MAX_BODY применяется после извлечения. Эксплойт парсеров не запускался и не подтверждён.

Воспроизведение: два заведомо невалидных контейнера приняты checkContent.

Исправление: проверять структуру контейнера, запрещать активное содержимое по выбранной политике; проверка антивирусом/карантином перед выдачей. Извлечение — в отдельном worker/процессе с лимитами памяти/CPU/времени, числа страниц и распакованных байтов; освобождать PDF-ресурсы. Не преобразовывать Word в HTML без отдельной очистки.

### SEC-07 · P2 · «26 МБ» не является жёстким ограничением входящего запроса

Места: `next.config.ts:9`, `deploy/Caddyfile`, API с `req.formData()`/`req.json()`.

`proxyClientMaxBodySize` ограничивает буфер Proxy и по документации Next.js не отклоняет превышение кодом 413. Caddy не задаёт `request_body max_size`. Проверки размеров файлов и строк идут после разбора тела. Злоумышленник может тратить ресурсы на большие тела/дополнительные multipart-поля и множество параллельных запросов; количество сохранённых файлов не ограничивает объём уже принятого запроса. Точный расход памяти данной сборки нагрузкой не измерялся.

Исправление: жёсткие лимиты на входе Caddy по типу маршрута, ограничения потокового чтения/парсера (Content-Length недостаточно для chunked), 413 до полной загрузки, лимиты одновременных загрузок и квоты хранения. Для маленьких JSON API лимиты существенно ниже, чем для документов.

### SEC-08 · P2 · Повторное подтверждение черновика создаёт дубли

Места: `src/app/reminder-actions.ts:15`, `src/app/(student)/assistant-actions.ts:19`, `src/app/teacher/assistant-actions.ts:25`, `src/app/staff/assistant-actions.ts:23`, `src/server/repos/assistant.ts:64`.

Проверка признака выполнения, создание объекта и markDraftDone — отдельные операции. Два параллельных запроса успевают пройти проверку. Подавление повторного клика в браузере не защищает сервер. Сбой после создания и до отметки тоже разрешает повтор. Возможны дубли заявок, заданий, объявлений и уведомлений.

Воспроизведение на реальном `createReminderAction` с подменёнными auth/БД: два конкурентных вызова для одного messageId оба вернули успех и выполнили два create. Остальные пути установлены чтением аналогичной последовательности, отдельный тест для каждого ещё нужен.

Исправление: уникальный серверный ключ операции по пользователю/черновику, создание объекта и фиксация результата в общей транзакции. Для внешних уведомлений — outbox. Существующий уникальный clientKey сообщений — полезный образец, хотя необходимо учесть семантику повторов.

### SEC-09 · P2 · Напоминание теряется при сбое создания уведомления

Место: `src/server/reminders.ts:12`.

sentAt устанавливается до `notify`; ошибка только логируется. Следующая доставка ищет sentAt=null и никогда не повторяет потерянное уведомление. Падение процесса между этими шагами даёт тот же эффект.

Воспроизведение: notify завершился исключением, повторная доставка не вызвала его ещё раз, напоминание осталось отмеченным отправленным.

Исправление: уведомление и завершение напоминания в одной транзакции, уникальность dedupeKey; push — через повторяемую очередь/outbox. Отдельно различать «записано в кабинет», «push отправлен» и «прочитано».

В появившемся во время аудита `src/server/proactive.ts` аналогично сначала записываются claim дневного слота и ключи подсказок, а потом создаётся чат: сбой между шагами подавляет повтор сводки. Это дополнительный путь той же ошибки доставки, установлен чтением, без отдельного воспроизведения.

## Дополнительные меры и решения перед реальной эксплуатацией

1. **Демо-режим.** Вход без пароля в деканат/преподавателя намеренно доступен по умолчанию, пример deploy/.env включает DEMO_LOGIN=1. Для конкурса это функция, для реальных данных — критичная конфигурация. Разделить стенды; включение демо сделать явным, запрещать его при production-real-data. Выключение кнопок не отключает известные пароли сид-аккаунтов: их удалить/заменить, проверить сид.
2. **Минимальные права БД.** Официальный postgres image создаёт POSTGRES_USER как суперпользователя; приложение использует его же. Выделить роль миграций и отдельную runtime-роль без superuser/DDL; тогда ошибка приложения не даёт автоматически права владельца всей БД. Фактические роли VPS не проверены.
3. **Лимиты входа.** Счётчики in-memory сбрасываются рестартом и не общие между процессами. Неактивные ключи Map не очищаются по таймеру; большое число разных логинов увеличивает память, параллельные запросы могут пройти до регистрации неудачи. Нужны ограниченное хранилище/TTL, предварительное резервирование попытки и ограничения на границе. MFA для деканата и преподавателей.
4. **Сессии и push.** Cookie Secure зависит от APP_URL; проверять обязательный HTTPS при старте production. Сессии — 30 дней без idle-timeout, токены хранятся открытым значением в БД: полезны хэширование session token и обзор активных устройств. При logout подписка push остаётся — определить поведение общего устройства. Для фотографий `private,max-age=300` допускает локальный кэш после смены аккаунта; для чувствительных фото предпочтителен no-store.
5. **Заголовки.** Уже есть nosniff, DENY, Referrer-Policy и HSTS на Caddy. Добавить CSP сначала Report-Only, затем enforce после проверки Next.js и inline-стилей; это усиление, а не найденный XSS. Для публичных QR-страниц — noindex и минимизация раскрываемых полей/логов.
6. **Deploy.** Новый app запускается до migrate deploy; возможен интервал несовместимой схемы. Разнести миграцию и переключение трафика, добавить health/readiness и откат. Добавить лимиты CPU/RAM/PID и ротацию логов. Production db/app не публикуют порты хоста — это правильная исходная настройка. Dev Compose публикует 5433 на всех интерфейсах с известным паролем: привязать к 127.0.0.1. Текущий embedded PG ограничен localhost-правилами pg_hba, его нельзя автоматически считать открытым наружу.
7. **Новые права библиотеки.** `knowledge.canEdit` позволяет факультетскому сотруднику менять/удалять любой UNIVERSITY-документ, а checkTarget — публиковать на весь вуз. Комментарий нового модуля допускает такую политику, поэтому это не объявляется подтверждённым обходом авторизации. Нужно явно утвердить право на общевузовые регламенты: соседний модуль объявлений запрещает такому сотруднику ALL. Для регламентов желательны версии, журнал и восстановление удалённого.
8. **ИИ.** Права проверяются сервером и модель не выполняет действия сама — хорошая основа. Перед подключением внешнего шлюза минимизировать передаваемые персональные данные; retrieved-текст считать недоверенным, отделять его от инструкций, проверять черновики и ссылки. В изученном коде не подтверждён обход доступа через prompt injection.

## Что выполнено и что не выполнено

- TypeScript: `node node_modules/typescript/bin/tsc --noEmit --incremental false` — успешно, включая файлы аудита, после переноса воспроизведений в docs/audits.
- ESLint: `node node_modules/eslint/bin/eslint.js` — успешно на промежуточном состоянии.
- 7 изолированных тестов воспроизведения дефектов: без реальной БД, сети и файловых записей приложения. PASS здесь означает «проблема воспроизведена», а не «защита работает». Специально исключены из обычного набора тестов.
- 6 существующих тестов маршрутизатора помощника — успешно.
- Общий интеграционный набор с засеянной БД не запускался: он меняет общие данные; в каталоге одновременно идёт другая работа. Не делаем вывода о прохождении всех 97 тестов.
- `corepack pnpm audit --json` не получен: Corepack не смог скачать требуемый менеджер (ECONNRESET), в том числе после запуска вне песочницы. **Проверка известных CVE зависимостей не завершена; отсутствие уязвимых зависимостей не подтверждено.** Исходные попытки typecheck/lint через Corepack также не дошли до самих проверок; затем запущены установленные локальные инструменты без обновления зависимостей.
- Production build, реальный Docker deployment, TLS/SSH/firewall/cron/backup-restore, браузерный пентест и нагрузочное тестирование не выполнялись. Без них вывод о безопасности действующего VPS невозможен.
- В проверенных участках пароли хэшируются Argon2id, session cookie httpOnly/SameSite=Lax, студент определяется из сессии, большинство чтений фильтруется по владельцу/факультету. Сырые SQL в сообщениях параметризованы. Эти наблюдения не заменяют полную матрицу негативных интеграционных тестов.
