# Подключение GigaChat к умному помощнику

Помощник работает в одном из трёх режимов. Режим задаётся переменной `AI_PROVIDER` в файле `.env`:

| `AI_PROVIDER` | Что работает |
|---|---|
| `rules` | Без внешней модели: встроенные правила и библиотека знаний. Режим по умолчанию. |
| `gigachat` | GigaChat (Сбер). |
| `gateway` | Любой OpenAI-совместимый шлюз. |

Если ключ не задан, неверен или GigaChat не отвечает, помощник сам переходит в режим правил: сайт не ломается.

## 1. Получить ключ

1. Войдите в личный кабинет GigaChat API (developers.sber.ru) и создайте проект.
2. Скопируйте **ключ авторизации** (Authorization key). Это длинная строка base64. Вместо неё подойдёт и пара `Client ID:Client Secret`: адаптер сам приведёт её к нужному виду.
3. Запомните тип доступа (scope):
   - `GIGACHAT_API_PERS` — для физических лиц;
   - `GIGACHAT_API_B2B` — для ИП и юрлиц с оплатой пакетами;
   - `GIGACHAT_API_CORP` — для ИП и юрлиц с оплатой по мере использования.
4. Выберите модель, доступную в вашем тарифе: `GigaChat`, `GigaChat-Pro` или `GigaChat-Max`.

Ключ — это секрет. Его нельзя хранить в коде, коммитах, `.env.example`, переписке и на скриншотах.

## 2. Сертификат Минцифры

Серверы GigaChat используют сертификат Национального удостоверяющего центра (НУЦ Минцифры). Node.js ему по умолчанию не доверяет, поэтому без него запросы падают с ошибкой TLS, и помощник остаётся в режиме правил.

1. Скачайте корневой сертификат «Russian Trusted Root CA» с официальной страницы Госуслуг: https://www.gosuslugi.ru/crt. Он публичный, это не секрет.
2. Сохраните его в формате PEM (текст начинается с `-----BEGIN CERTIFICATE-----`) под именем `russian_trusted_root_ca.pem`:
   - **локально** — в папку `certs/` в корне проекта;
   - **на сервере** — в `deploy/certs/` рядом с `deploy/.env`. Docker подключает эту папку в контейнер как `/app/certs`.
3. Укажите путь к файлу в `GIGACHAT_CA_FILE`, как показано ниже.

Если файл скачался в двоичном формате (`.cer`/DER), переведите его в PEM:

```powershell
certutil -encode russian_trusted_root_ca.cer russian_trusted_root_ca.pem
```

## 3. Куда записать ключ

### Локально

Файл `.env` в корне проекта: `digital-dekanat\.env`. Он уже есть и не попадает в git.

```
AI_PROVIDER="gigachat"
GIGACHAT_AUTH_KEY="…ключ авторизации…"
GIGACHAT_SCOPE="GIGACHAT_API_PERS"
GIGACHAT_CA_FILE="./certs/russian_trusted_root_ca.pem"
AI_MODEL="GigaChat"
```

После правки перезапустите сайт. `.env` читается только при старте.

### На сервере (VPS)

Файл `/opt/univer/deploy/.env` с правами `600`: читать и менять его может только владелец.

```
AI_PROVIDER=gigachat
GIGACHAT_AUTH_KEY=…ключ авторизации…
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_CA_FILE=/app/certs/russian_trusted_root_ca.pem
AI_MODEL=GigaChat
```

Затем перезапустите приложение:

```bash
cd /opt/univer/deploy && docker compose up -d app
```

Чего делать нельзя:
- писать ключ в `.env.example` и `deploy/.env.example`: они лежат в git, в них только пустые названия;
- называть переменную с префиксом `NEXT_PUBLIC_`: такая переменная попадает в браузер.

## 4. Как проверить

1. Откройте помощника студента и задайте вопрос не по шаблону, например «Объясни, как мне подготовиться к сессии».
2. Ответ модели связный и опирается на данные кабинета. В режиме правил помощник предлагает темы и кнопки.
3. Если ответ остался шаблонным, смотрите журнал сервера:
   - локально — окно, где запущен `pnpm dev`;
   - на сервере — команда `docker compose logs app --tail 50`.

   Возможные строки:
   - `GigaChat OAuth HTTP 401` — неверный ключ или scope;
   - `GigaChat HTTP 402` — закончился пакет токенов;
   - `GigaChat error … self-signed certificate` или `unable to get local issuer certificate` — не найден сертификат, проверьте `GIGACHAT_CA_FILE`.

   Ключ в журнал не пишется.

## Как это устроено

Код находится в `src/server/ai/llm.ts`.

1. По ключу авторизации сервер получает временный токен доступа: `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth`. Токен живёт около 30 минут. Адаптер хранит его в памяти и обновляет за минуту до истечения. Если GigaChat ответил 401, адаптер один раз берёт новый токен и повторяет запрос.
2. Запросы к модели отправляются на `https://gigachat.devices.sberbank.ru/api/v1/chat/completions` с этим токеном.
3. Так же устроены все функции помощника: ответы студенту, черновики заявок, черновики переноса и объявлений у деканата, отметка посещаемости у преподавателя. Любое действие выполняется только по кнопке пользователя и проверяется на сервере, независимо от того, какая модель подготовила черновик.

Адреса можно переопределить переменными `GIGACHAT_OAUTH_URL` и `GIGACHAT_API_URL`, но для обычной работы это не нужно.
