## 1. Стек
| Слой | Выбор | Почему |
|---|---|---|
| Приложение | **Next.js 15 (App Router) + TypeScript**, один процесс: UI + API (Route Handlers + Server Actions) | Один репозиторий, один деплой, SSR для скорости на телефоне. Агенты знают стек лучше всего — меньше ошибок ИИ. |
| UI | **Tailwind CSS 4 + shadcn/ui** (Radix), иконки **lucide-react**, шрифт **Manrope** (Google Fonts, OFL) | Все MIT/ISC/OFL. Готовые доступные компоненты (диалоги, табы, формы) → быстрее и качественнее. |
| Данные | **PostgreSQL 16 + Prisma ORM** | Нормальная СУБД: масштабируется вертикально и репликами; Prisma даёт типы и миграции. |
| Валидация | **Zod** (формы и API) | Одна схема на клиент и сервер. |
| Аутентификация | **Своя, минимальная**: `@node-rs/argon2` (argon2id), таблица `Session`, cookie `httpOnly; Secure; SameSite=Lax` | Auth.js/NextAuth для логина-пароля — лишняя сложность и типичный источник ошибок ИИ. 150 строк своего кода проще проверить. |
| PDF и QR | `pdf-lib` + `qrcode` | Чистый JS, без Chromium на сервере. |
| Данные на клиенте | **SWR** для лент (уведомления, статусы) с опросом 20–30 с | Проще и надёжнее WebSocket/SSE для прототипа; обновление «почти сразу». |
| Тесты | **Vitest** (авторизация, бизнес-логика) + **Playwright** (e2e, мобильный viewport) | Минимум, который доказывает работу жюри и ловит регрессии. |
| Деплой | **Docker Compose**: `app` + `postgres` + `caddy` (автоматический HTTPS) | Изолированно от того, что уже есть на VPS. |

**Масштабирование (для жюри и для отчёта):** приложение stateless (сессии в БД), значит, можно поднять N реплик за балансировщиком; PostgreSQL — read-реплики и пул соединений (PgBouncer); тяжёлое (PDF, рассылки) выносится в очередь (BullMQ + Redis) без изменения кода экранов. Для прототипа всё это не нужно, но путь прямой.

## 2. Модель данных (Prisma)
Все ID — `cuid()` (непредсказуемые, не перебираются). Время — `timestamptz`.

```
User        id, login (unique), passwordHash, role: STUDENT|STAFF, createdAt
Session     id, userId→User, expiresAt, createdAt, userAgent?
Student     id, userId→User (unique), lastName, firstName, middleName?, facultyId→Faculty,
            programId→Program, course (1..6), groupId→Group, subgroup (1|2), recordBookNo (вымышленный), email?
Staff       id, userId→User (unique), fullName, position, facultyId?→Faculty
Faculty     id, name, shortName
Program     id, facultyId→Faculty, name, code (напр. 09.03.01)
Group       id, programId→Program, name (напр. ИВТ-21-2), course
Teacher     id, fullName, department           # вымышленные, без кабинета
Course      id, name, department, assessment: EXAM|CREDIT|GRADED_CREDIT|COURSEWORK
Lesson      id, groupId→Group, subgroup? (null = вся группа), courseId→Course, teacherId→Teacher,
            date, startTime, endTime, room, building, kind: LECTURE|PRACTICE|LAB|EXAM|CONSULTATION,
            status: SCHEDULED|MOVED|CANCELLED, movedFromDate?, movedFromTime?, changeNote?, changedAt?
Enrollment  id, studentId→Student, courseId→Course, semester (напр. "2026-1")
Grade       id, enrollmentId→Enrollment, kind: CURRENT|MIDTERM|FINAL|RETAKE, value (2..5 | PASS | FAIL | null),
            points? (0..100), date, note?
Exam        id, courseId→Course, groupId→Group, date, time, room, kind: EXAM|CREDIT|RETAKE
Debt        (вычисляется: FINAL = 2/FAIL/null после даты экзамена) — не таблица, а запрос
RequestType id, code (CERT_STUDY|CERT_MILITARY|CERT_SCHOLARSHIP|APP_RETAKE|APP_ABSENCE|APP_ACADEMIC_LEAVE|APP_OTHER),
            title, description, needsPaper (bool), fields (JSON-схема доп. полей), slaDays
Request     id, studentId→Student, typeId→RequestType, status: NEW|IN_REVIEW|NEED_INFO|READY|DONE|REJECTED,
            payload (JSON: доп. поля), comment?, wantsPaper (bool), createdAt, updatedAt, assigneeId?→Staff
RequestEvent id, requestId→Request, fromStatus?, toStatus, authorUserId→User, message?, createdAt
Certificate id, requestId→Request (unique), verifyCode (unique, 12 симв. из безопасного генератора),
            issuedAt, validUntil, pdfPath, revoked (bool)
Announcement id, title, body (markdown-lite), audience: ALL|FACULTY|GROUP, facultyId?, groupId?,
            pinned (bool), authorStaffId→Staff, publishedAt
Deadline    id, title, dueAt, audience (как у Announcement), courseId?, link?
Notification id, userId→User, kind: SCHEDULE_CHANGE|REQUEST_STATUS|ANNOUNCEMENT|DEADLINE|GRADE|SYSTEM,
            title, body, link?, readAt?, createdAt, dedupeKey? (unique с userId)
WellbeingCheckin id, studentId→Student, weekStart, mood (1..5), createdAt   # опционально
AiMessage   id, studentId→Student, role: USER|ASSISTANT, content, createdAt, draftRequestId?→Request
```

Индексы: `Lesson(groupId, date)`, `Notification(userId, readAt, createdAt)`, `Request(studentId, createdAt)`, `Grade(enrollmentId)`.

**Сид (`prisma/seed.ts`)**: 3 факультета, 6 направлений, 8 групп, 25 преподавателей, 40 дисциплин, расписание на текущую и следующую неделю для всех групп (с 2–3 переносами и 1 отменой в группах тестовых студентов), оценки за 2 прошлых семестра + текущие, 1 долг у второго студента, 3–4 заявки в разных статусах, 6 объявлений, 5 дедлайнов. Генерация — детерминированная (`seedrandom`), чтобы демо было воспроизводимо. Все ФИО — из генератора вымышленных имён.

## 3. Вход, сессии, разделение данных
### 3.1 Вход
- `POST /api/auth/login` {login, password} → argon2id verify → создать `Session` (30 дней, продление при активности) → cookie `sid` (`httpOnly`, `Secure`, `SameSite=Lax`, `Path=/`).
- Ограничение попыток: in-memory счётчик по `login+IP`, 10 попыток / 15 мин → 429 с понятным текстом. (Для прототипа достаточно; на проде — Redis.)
- `POST /api/auth/logout` — удаление сессии и cookie.
- Ошибка входа — одна формулировка «Неверный логин или пароль» (без утечки, существует ли логин).
- Пароли только хэш (argon2id, memory 64 МБ, time 3). В сиде пароли задаются открытым текстом только в скрипте сидирования и хэшируются при записи.

### 3.2 Авторизация — единая точка
```
src/lib/auth.ts
  getSession()            → Session+User | null   (читает cookie, проверяет expiresAt)
  requireStudent()        → { user, student }      иначе redirect('/login') / 401 в API
  requireStaff()          → { user, staff }        иначе 403
```
**Правило №1: в коде нет маршрутов и запросов с чужим `studentId` из URL.** Студенческие данные всегда берутся как `where: { studentId: student.id }`, где `student` — из `requireStudent()`. URL-ы студента — `/requests/[id]`, но запрос `findFirst({ where: { id, studentId: student.id } })` → если чужое, получаем `null` → 404. Так подмена ID в адресе и в API даёт 404, не отличимый от «не существует».

**Правило №2: data-access слой.** Все обращения к Prisma — только через `src/server/repos/*.ts`; функции принимают `studentId` первым аргументом и не имеют варианта «без фильтра». Страницы и API Prisma напрямую не вызывают. Это проверяется тестом-линтом (grep на `prisma.` вне `src/server`).

**Правило №3: сотрудник ≠ студент.** Сотрудник видит заявки, объявления, расписание своего факультета, но **не** может открыть `/` студента, его оценки или уведомления; у него свой layout `/staff/*`. Студент не может открыть `/staff/*` (403 → страница «Нет доступа»).

### 3.3 Модель угроз
| Угроза | Мера |
|---|---|
| IDOR (чужая заявка/справка/профиль по ID) | Правила 1–2; cuid вместо числовых ID; e2e-тест «студент A открывает заявку студента B → 404» |
| Подбор пароля | argon2id, лимит попыток, пароли тестовых аккаунтов ≥ 12 символов |
| Кража cookie | `httpOnly`, `Secure`, HTTPS через Caddy; сессия отзывается по logout |
| CSRF | Server Actions защищены Next.js (origin check); API-мутации принимают только JSON с `SameSite=Lax` cookie; дополнительно проверяем `Origin` в middleware для `POST` |
| XSS | React экранирует; markdown объявлений рендерим через `marked` + `DOMPurify` (или без HTML — только переносы и ссылки) |
| Утечка секретов | `.env` в `.gitignore`; ключи ИИ только на сервере; клиент ходит к `/api/assistant`, никогда к провайдеру напрямую; `git-secrets`-подобная проверка в CI (grep на `sk-`, `GIGA`) |
| Утечка чужих данных через ИИ | Ассистент получает контекст, собранный сервером только по `student.id`; у модели нет инструментов с доступом к БД (§6) |
| Публичная проверка справки | `/verify/[code]` показывает минимум: тип, ФИО, группа, дата выдачи, «действительна/отозвана». Код — 12 символов, не перебирается |
| Rate limit API ассистента | 20 сообщений / 10 мин на студента |
| Логи | Не логировать пароли, тела заявок, сообщения ассистента целиком |

## 4. Экраны и сценарии (mobile-first, 360 px)
### 4.1 Навигация
- **Телефон:** нижняя панель из 5 вкладок: **Сегодня · Расписание · Учёба · Заявки · Ещё** (Ещё → уведомления, профиль, помощник, выход). Колокольчик с бейджем непрочитанных — в шапке на всех экранах.
- **Десктоп (≥1024):** левый сайдбар с теми же пунктами + помощник.
- Шапка: название кабинета, пометка **«Концепт для конкурса — не официальный сервис вуза»** (постоянно, мелким текстом в футере и на экране входа крупно).

### 4.2 Карта экранов — студент
| Маршрут | Экран | Содержимое и состояния |
|---|---|---|
| `/login` | Вход | Логин, пароль, кнопка; ошибка inline; подсказка «тестовые аккаунты — в описании работы». Пометка о концепте. |
| `/` | **Мой день** | 1) Карточка «Сейчас/следующая пара»: дисциплина, аудитория, преподаватель, обратный отсчёт; 2) Лента пар на сегодня (переносы — янтарный бейдж «Перенесено», отмены — зачёркнуто); 3) «Требует внимания» — до 5 карточек: дедлайны ≤7 дней, заявка сменила статус, долг/пересдача, новое объявление, непрочитанные; 4) Чек-ин настроения (1 строка, опционально). Пустые состояния: «Сегодня пар нет 🎉», «Всё спокойно». |
| `/schedule` | Расписание | Табы День/Неделя; свайп/стрелки по дням; переключатель недели (чёт/нечет не нужен — расписание датированное); изменения подсвечены + баннер «3 изменения на этой неделе»; кнопка «В календарь» (`.ics` за 4 недели). Офлайн: последняя загруженная неделя кэшируется в `localStorage` и показывается с пометкой «данные от …». |
| `/grades` | Учёба | Сверху сводка: средний балл, «Долгов: 0» зелёным / «1 долг» красным, ближайшая сессия (дата первого экзамена); табы по семестрам; список дисциплин с оценкой/зачётом и формой контроля; блок «Сессия»: экзамены с датами и аудиториями, пересдачи. Пустое: «Оценок пока нет». |
| `/requests` | Заявки | Список с цветными статусами и датой; кнопка «Новая заявка». Пустое: иллюстрация + «Закажите справку за минуту». |
| `/requests/new` | Новая заявка | Шаг 1 — выбор типа (карточки с описанием и сроком); шаг 2 — форма по `fields` типа + чекбокс «Нужна бумажная копия с печатью» (подсказка: «для военкомата и некоторых банков»); шаг 3 — подтверждение. |
| `/requests/[id]` | Заявка | Трекер статусов (как у доставки): Новая → В работе → Готова → Выдана; история событий с комментариями сотрудника; при `READY` — кнопка «Скачать PDF» и QR; при `NEED_INFO` — поле ответа. |
| `/notifications` | Уведомления | Лента по дням, фильтр Все/Непрочитанные; клик → `link`; «Прочитать все». Объявления деканата — отдельный таб. |
| `/assistant` | Помощник | Чат; быстрые кнопки «Нужна справка», «Как перенести пересдачу», «Что у меня на неделе»; ответ может содержать карточку «Черновик заявки» → кнопка «Проверить и отправить» → `/requests/new?draft=…`. Дисклеймер: «Ответы ИИ, проверяйте в деканате». |
| `/profile` | Профиль | ФИО, факультет, направление, курс, группа/подгруппа, № зачётки (вымышленный); смена пароля; выход. |
| `/verify/[code]` | Проверка справки (публичная) | Статус, тип, ФИО, группа, дата выдачи, срок; без входа. |

### 4.3 Сквозной сценарий (его проходит жюри)
Вход → «Мой день» (видит перенесённую пару) → Расписание (неделя, изменение подсвечено) → Учёба (оценки, 1 долг) → Заявки → Новая → «Справка об обучении» → отправить → статус «Новая» → *(сотрудник переводит в «Готова»)* → через ≤30 с студент видит уведомление и статус «Готова» → скачивает PDF с QR → открывает `/verify/…`.

### 4.4 Карта экранов — сотрудник деканата (`/staff/*`)
| Маршрут | Содержимое |
|---|---|
| `/staff` | Сводка: новых заявок N, просроченных по SLA M, быстрые действия. |
| `/staff/requests` | Таблица/список с фильтрами по статусу и типу; на телефоне — карточки. |
| `/staff/requests/[id]` | Данные студента (только нужное: ФИО, группа), payload, смена статуса с комментарием, «Сформировать справку» (генерирует PDF + QR и ставит READY), «Запросить уточнение». |
| `/staff/announcements` | Создать/закрепить объявление (аудитория: все/факультет/группа) → уведомления адресатам. |
| `/staff/schedule` | Выбор группы и даты → перенести/отменить пару (дата, время, аудитория, причина) → уведомления группе. |

### 4.5 Состояния, которые обязательны на каждом экране
Загрузка — скелетоны (не спиннер на весь экран); пустое — текст + действие; ошибка — текст + «Повторить»; офлайн — баннер. Формы: валидация Zod на клиенте и сервере, сообщения по-русски, кнопка блокируется на время отправки.

### 4.6 Доступность и скорость
Контраст ≥ 4.5:1, фокус видим, размер касания ≥ 44 px, `aria-label` на иконках-кнопках, `prefers-reduced-motion`. SSR экранов, динамический импорт PDF/QR-библиотек, изображений почти нет. Цель: LCP < 2 с на 3G-fast.

## 5. Дизайн-направление
- **Характер:** спокойный, «как у хорошего банковского приложения», не корпоративно-казённый. Много воздуха, крупные заголовки, карточки с мягкими тенями, скругления 16 px.
- **Цвет:** основа нейтральная (slate), акцент — глубокий сине-зелёный (`#0F766E`), статусы: янтарный (перенос/в работе), красный (отмена/долг/отклонено), зелёный (готово). Тёмная тема — через CSS-переменные shadcn, переключатель в «Ещё».
- **Типографика:** Manrope (OFL), 16 px базовый, заголовки 24/20.
- **Логотип:** свой: монограмма «Л» в форме волны/паруса (Ладога) — SVG, генерируем ИИ (идея) и дорабатываем руками. Не копирует ни один реальный логотип.
- **Иллюстрации пустых состояний:** простые line-art SVG, сгенерированные ИИ, или `undraw.co` (лицензия разрешает). Лицензии перечислить в `docs/licenses.md`.

## 6. ИИ-помощник
```
src/server/ai/
  provider.ts      interface AiProvider { chat(messages, opts): Promise<AiReply> }
  gigachat.ts      реализация через HTTPS API GigaChat (OAuth по client secret из env, токен кэшируется)
  rules.ts         fallback без сети: сопоставление намерений (справка/пересдача/расписание/оценки) по ключевым словам
  context.ts       buildStudentContext(studentId): компактный текст — профиль, расписание на 7 дней,
                   долги, активные заявки, ближайшие дедлайны (только данные этого студента)
  assistant.ts     orchestrate(): контекст + системный промпт + история (последние 10) → ответ;
                   структурированный ответ { text, draft?: {typeCode, payload} }
```
- **Выбор провайдера** — `AI_PROVIDER=gigachat|rules` в env. Без ключа — `rules`, демо не ломается. Ключ — только `GIGACHAT_CREDENTIALS` на сервере.
- **Защита данных:** модель не вызывает БД; весь контекст уже отфильтрован по `student.id`. Системный промпт: «Отвечай только по данным из контекста; если данных нет — предложи обратиться в деканат». Черновик заявки — это JSON в ответе, который сервер валидирует Zod-схемой типа заявки, прежде чем показать.
- **Альтернативы** (если команда решит): YandexGPT (нужен аккаунт Yandex Cloud и платёжный профиль), любой OpenAI-совместимый прокси вне РФ (минус: сложнее объяснить жюри). Интерфейс один, замена — один файл.
- **Что ассистент умеет в прототипе:** ответить на вопрос о расписании/оценках/долгах; подобрать тип справки и заполнить черновик; объяснить порядок пересдачи/академа (тексты «положений» вуза — вымышленные, лежат в `src/server/ai/knowledge.md` и подмешиваются в промпт).

## 7. Справки с QR
1. Сотрудник нажимает «Сформировать справку» (или автоматически для типов `CERT_*` при переводе в READY).
2. `certificates.ts`: генерируем `verifyCode` (`nanoid(12)` из алфавита без похожих символов), собираем PDF (`pdf-lib`: шапка вуза без логотипа реального вуза, текст справки, QR с URL `https://<host>/verify/<code>`, подпись «Документ сформирован в электронном виде; проверка подлинности по QR»), сохраняем в `/data/certificates/<id>.pdf` (Docker volume).
3. Скачивание — `GET /api/certificates/[id]/pdf` только владельцем (через `requireStudent` + проверка `request.studentId`) или сотрудником.
4. `/verify/[code]` — публичная, без PII сверх необходимого, показывает «действительна до …» или «отозвана».
5. Если `wantsPaper` — заявка после READY получает событие «Бумажная копия готова, заберите в каб. 204» (имитация).

## 8. Уведомления
- Таблица `Notification`; создаются сервисом `notify(userIds, kind, title, body, link, dedupeKey)` из событий: смена статуса заявки, перенос/отмена пары (всей группе/подгруппе), объявление (по аудитории), дедлайн (крон-джоб в приложении раз в час: напоминание за 3 дня и за 1 день, dedupeKey не даёт дублей), новая оценка.
- Клиент: SWR `GET /api/notifications/unread-count` каждые 20 с на всех экранах; лента — по запросу. Это даёт «сотрудник изменил статус — студент увидел» в пределах 20 с, достаточно для демо.
- **Web Push — не делаем** (VAPID, разрешения, iOS-ограничения; высокий риск потерять время). В отчёте: «следующий шаг».
- Объявления деканата — отдельная сущность, в ленте уведомлений показываются как карточки, плюс закреплённые — на «Моём дне».

## 9. Деплой на VPS Jino
### 9.1 Состав
```
deploy/
  docker-compose.yml   app (node:22-alpine, next start), postgres:16-alpine (volume pgdata), caddy:2 (volumes caddy_data, caddy_config)
  Caddyfile            7d965724e284.vps.myjino.ru { reverse_proxy app:3000 }   # автоматический Let's Encrypt
  .env.example         DATABASE_URL, SESSION_SECRET, AI_PROVIDER, GIGACHAT_CREDENTIALS, APP_URL
  backup.sh            pg_dump в /opt/dekanat/backups/YYYY-MM-DD.sql.gz, хранить 14 дней; cron ежедневно 03:00
  deploy.sh            git pull → docker compose build → compose up -d → prisma migrate deploy → (первый раз) seed
```
Dockerfile — multi-stage (`pnpm install --frozen-lockfile` → `next build` с `output: 'standalone'` → runtime-образ ~150 МБ). Сборка на VPS (8 ГБ хватает); при проблемах — сборка в GitHub Actions и `docker pull` с GHCR.

### 9.2 Что проверить на VPS перед установкой (ничего не менять)
`uname -a; free -h; df -h; ss -tlnp | grep -E ':80|:443'; docker --version; docker ps; systemctl list-units --type=service --state=running | head -40`. Если Docker нет — ставим официальным скриптом (это единственное системное изменение). Всё наше — в `/opt/dekanat`.

### 9.3 Переменные и секреты
`.env` только на сервере (`chmod 600`), создаётся вручную из `.env.example`. `SESSION_SECRET` — `openssl rand -hex 32`. В репозитории — только `.env.example` с пустыми значениями.

### 9.4 Если 80/443 заняты
Вариант А (предпочтительный): существующий сервис — тоже Caddy/Nginx → добавляем в него виртуальный хост на наш `app:3000`. Вариант Б: наш Caddy на 8443 (`https://host:8443`) — сертификат LE через HTTP-челлендж не получить, значит TLS-ALPN на 443 тоже не наш → используем DNS-челлендж невозможно (не наш домен) → тогда самоподписанный сертификат и предупреждение браузера. Поэтому при занятых портах — только вариант А.

### 9.5 Обновление
`ssh … 'cd /opt/dekanat && ./deploy.sh'`. Миграции — `prisma migrate deploy`, откат — восстановление из бэкапа. Логи — `docker compose logs -f app`.

## 10. Тестирование (минимум)
| Тип | Что | Инструмент |
