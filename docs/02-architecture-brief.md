# Задание на архитектуру (для Claude Fable)

## Контекст
Команда участвует в конкурсе: нужно за несколько дней собрать работающий прототип «цифрового деканата будущего» — личного кабинета студента. Код пишут ИИ-агенты (Claude Code: Opus как оркестратор и основной разработчик, Sonnet/Haiku — субагенты для рутины). Твоя роль — архитектор: от твоего документа зависит, насколько быстро и без переделок агенты соберут продукт.

Прочитай перед работой:
- `docs/00-tz.md` — требования конкурса и критерии оценки;
- `docs/01-research.md` — что нужно студентам, и в конце — уже принятое решение по составу разделов и ролей.

## Что уже решено
- Роли: **студент** и **сотрудник деканата**. Преподаватель и полноценная админка — вне рамок.
- Состав разделов и фишек — раздел «Решение команды по составу» в `01-research.md`.
- **Скорость важнее всего.** Делаем максимально быстро, без календарного графика: план — это порядок задач по приоритету, без оценок по дням. Сначала сквозной рабочий сценарий ядра, затем полировка и фишки.
- Хостинг: **VPS на Jino** (Россия): 2 vCPU × 2 ГГц, 8 ГБ RAM, диск 49 ГБ (свободно ~24 ГБ), root по SSH. **На сервере уже что-то работает** (~2 ГБ RAM занято) — наш деплой не должен мешать существующим сервисам: изолированный Docker Compose, проверка занятости портов 80/443 перед установкой, без глобальных изменений системы.
- **Без собственного домена**: у VPS есть технический поддомен Jino вида `*.vps.myjino.ru` — по нему можно получить сертификат Let's Encrypt и дать жюри HTTPS-ссылку. Если 80/443 заняты другим сервисом — предложи вариант (общий reverse proxy или другой порт).
- Репозиторий: `github.com/SetOffice24/digital-dekanat` (приватный, доступ жюри дадим позже).
- Разработка на Windows 10, Node.js 24, pnpm через corepack, Docker на VPS.

## Что нужно от тебя
Документ `docs/ARCHITECTURE.md` — достаточный, чтобы агенты-разработчики работали по нему без уточнений. Стек выбирай сам, с коротким обоснованием; ориентир команды — Next.js + TypeScript + PostgreSQL, но если видишь вариант лучше для сроков и требований — предлагай.

Что должно быть в документе:
1. **Стек и обоснование** — включая масштабирование под разное число пользователей (критерий жюри).
2. **Модель данных** — сущности, связи, поля; что генерируется сидом.
3. **Вход и авторизация** — хранение паролей, сессии, роли; как гарантируется «студент видит только своё» (в том числе подмена ID в URL и в API), что видит сотрудник. Модель угроз с мерами.
4. **Карта экранов и сценариев** — mobile-first (от 360 px): навигация, главный экран «Мой день», путь «войти → расписание → оценки → подать заявку → увидеть статус», путь сотрудника; пустые состояния, ошибки, загрузка.
5. **Дизайн-направление** — визуальный характер, основа дизайн-системы, лицензии на шрифты и иконки.
6. **ИИ-помощник** — как устроен, какие данные ему доступны и как не дать ему выдать чужие данные; где хранится ключ. **Важно:** OpenAI и Anthropic API недоступны с российских IP, поэтому учти провайдера, доступного с VPS (например GigaChat или YandexGPT), либо альтернативу; оформи это как выбор с вариантами.
7. **Справки с QR** — генерация PDF, страница проверки подлинности.
8. **Уведомления** — как появляются (события: перенос, смена статуса, объявление, дедлайн), реальное время или опрос, web push — стоит ли.
9. **Деплой** — Docker Compose на VPS, HTTPS, бэкапы БД, переменные окружения, как обновлять.
10. **Тестирование** — минимальный набор: сценарии e2e, тесты на разделение данных.
11. **План реализации** — задачи по приоритету, для каждой: что сделать, критерий готовности, какой модели поручить (Opus / Sonnet / Haiku) и что можно делать параллельно. Без оценок по дням.
12. **Риски** и что упростить, если задача тормозит.

Пиши кратко и конкретно: таблицы и списки лучше прозы. Объём — сколько нужно, но без воды.
