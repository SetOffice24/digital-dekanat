# Отчёт для жюри — пространство обсуждения

Здесь агенты и команда обсуждают конкурсное описание процесса создания («как мы работали с нейросетями»). Код сервиса эта папка не затрагивает. В Docker-образ она не попадает (`.dockerignore`).

## Где сам отчёт

Чистовик — документ Claude Docs «„Цифровой деканат“: как мы создавали кабинет с нейросетями». Ссылку даёт команда. Из документа делается PDF для подачи.

Для агентов без доступа к документу (ChatGPT/Codex, Kimi и другие) полный текст лежит в `otchet.md`, со ссылками на скриншоты из `screenshots/`. Это копия документа, а не отдельная версия. Читайте её, а правки предлагайте репликой в карточке обсуждения; сам `otchet.md` не редактируйте.

Перенос согласованных правок в документ делает координатор: команда или агент, которому она это поручила. После каждого изменения документа координатор обновляет `otchet.md`, чтобы копия совпадала с ним.

## Требования конкурса к описанию

1. Какую проблему студентов решает кабинет и почему выбраны эти разделы; что узнали от однокурсников, если спрашивали.
2. Полный перечень ИИ-инструментов, IDE и сервисов (код, дизайн, тексты, картинки) и для чего каждый.
3. Ключевые промпты и диалоги с ИИ-ассистентами с привязкой к этапам и функциям.
4. Скриншоты ключевых шагов: от идеи и макета до готового кабинета, удачные и неудачные варианты.
5. Как устроены вход, хранение данных и защита — простыми словами.
6. Этапы, проделанные вручную.

## Источники фактов

- `docs/process-log.md` — журнал этапов, инструментов, промптов и ошибок ИИ.
- `docs/01-research.md` — исследование болей студентов.
- `docs/audits/` — аудиты Codex и Kimi.
- `docs/ARCHITECTURE.md`, `docs/HANDOFF.md`, `AGENTS.md` — устройство и правила.
- `docs/jury-access.md` — адрес и вымышленные аккаунты.
- История git — для скриншотов ранних версий.

В отчёт попадает только то, что подтверждается этими источниками или словами команды. Нельзя:
- называть исследование отзывов опросом однокурсников;
- выдавать действия агента в браузере за ручной труд человека;
- заявлять юридическую значимость справки, измеренный эффект или промышленную нагрузку.

## Как обсуждать

- Карточки: `R-YYYYMMDD-kratkoe-nazvanie.md`. Главная — `R-20261122-otchet-dlya-zhyuri.md`.
- Новая реплика добавляется в конец раздела «Обсуждение». Формат:

  ```
  ### YYYY-MM-DD · <инструмент/модель> · <Правка / Возражение / Вопрос / Факт>
  **Раздел отчёта:** <название раздела>
  **Что не так или чего не хватает:** <конкретно, со ссылкой на источник>
  **Предложение:** <готовый текст или действие>
  ```

- Чужие реплики не править и не удалять. Возражение оформляется новой репликой.
- Одну карточку в один момент меняет один участник.
- Решение, что войдёт в отчёт, принимает команда. Консенсус агентов его не заменяет.
- Секреты и реальные персональные данные сюда не писать. Пароли вымышленных аккаунтов уже есть в `docs/jury-access.md`, дублировать их не нужно.

## Скриншоты

Скриншоты лежат в `docs/report/screenshots/`, имя файла начинается с номера этапа: `03-design-v1-desktop.png`, `10-student-day-mobile.png`. Снимать только с вымышленными данными. Ранние версии снимаются запуском старого коммита локально, а не рисуются заново.
