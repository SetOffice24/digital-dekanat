# Выкладка на service.setoffice.ru

**Сервер:** Jino VPS (81.177.6.131), Ubuntu 24.04, Docker 29, Compose v5. HTTPS обрабатывает прокси Jino: он передаёт запросы по http на nginx сервера (порт 80), адрес посетителя кладёт в X-Forwarded-For. На сервере работают и другие сервисы. Снаружи доступны только веб и SSH (порт 49264), остальные порты Jino не пропускает (проверено 22.11).

**Схема:** nginx → `127.0.0.1:3210` → контейнер приложения → контейнер PostgreSQL. Наш Caddy не используется. База и приложение снаружи напрямую недоступны.

**Папка:** `/var/www/service.setoffice.ru/app` — клон репозитория. Сейчас nginx раздаёт `/var/www/service.setoffice.ru` как статику (там лежит `cover.jpg`). После настройки он раздавать файлы не будет, всё уходит в приложение. Код и `deploy/.env` не должны быть доступны по ссылке.

## Шаги

Все шаги выполняются только по команде команды. Пароли и ключи вводит пользователь.

1. **Осмотр, без изменений.** Есть ли Docker и Compose, свободен ли порт 3210, где лежит конфигурация nginx для `service.setoffice.ru` и пути к её сертификату.
2. **Код.** `git clone` приватного репозитория в `/var/www/service.setoffice.ru/app`. Серверу нужен доступ к GitHub: deploy-ключ только на чтение или временный токен.
3. **`deploy/.env`** заполняет пользователь по шаблону `deploy/.env.example`, права `chmod 600`. Обязательные строки:
   - `APP_URL=https://service.setoffice.ru`;
   - `APP_PORT=3210`;
   - `DB_PASSWORD=` — длинный случайный пароль.

   При необходимости — переменные GigaChat, см. `docs/GIGACHAT.md`. Сертификат Минцифры кладётся в `deploy/certs/`. Строку `DEMO_LOGIN=1` **не добавлять**: быстрый вход на опубликованном сервисе выключен.
4. **Запуск:** `cd /var/www/service.setoffice.ru/app/deploy && ./deploy.sh --seed`. Скрипт:
   - собирает образ;
   - поднимает базу и приложение;
   - применяет миграции;
   - создаёт ключи push-уведомлений;
   - заполняет демо-данные.
5. **nginx.** Сохранить копию текущего `/etc/nginx/conf.d/service.setoffice.ru.conf`. Заменить его на `deploy/nginx/service.setoffice.ru.conf`: прокси на 3210, адрес посетителя через realip, условный редирект на https; сертификаты не нужны. Затем `nginx -t && systemctl reload nginx`.
6. **Проверка.** Адрес открывается с телефона по HTTPS. Вход по каждому логину из `docs/jury-access.md` работает. На странице входа нет кнопок быстрого входа. Справка с QR скачивается, помощник отвечает.
7. **Резервная копия:** cron `0 3 * * * /var/www/service.setoffice.ru/app/deploy/backup.sh`.

## Обновление

`cd /var/www/service.setoffice.ru/app/deploy && ./deploy.sh`. Без `--seed` данные сохраняются. С `--seed` демо-данные пересоздаются, и все входы сбрасываются.
